# Шийдвэрийн бүртгэл

ERP системийн талаар хэрэглэгчтэй тохиролцсон шийдвэрүүд. Шинэ шийдвэрийг огноотойгоор нэмнэ.
Шинэ session эхлэхдээ эндээс уншиж, үргэлжлүүлнэ.

## 2026-10-28

### Ажиллах зарчим

- Компанид техникийн мэдлэгтэй хүн байхгүй. Кодыг бичих, байршуулах, баримтжуулах ажлыг бүхэлд нь Claude хийнэ.
- Тиймээс бүх зүйл автомат байна: GitHub-д push хийхэд автоматаар байршина, өдөр бүр backup хийнэ, систем унавал хэрэглэгчид мэдэгдэл очно.
- Claude өмнөх яриагаа санахгүй. Шийдвэр, явцыг энэ `docs/` хавтсанд хадгална.
- Сервер, домэйн, GitHub, Cloudflare бүртгэлүүд компанийн нэр дээр байна.
- Хэрэглэгчтэй монгол хэлээр, техникийн үг аль болох цөөн хэрэглэж харилцана.

### Компани

- 50 орчим ажилтан. Хэд хэдэн ХХК-тай.
- ХХК бүрийн мэдээлэл тусдаа хадгалагдана. Нэг ажилтан хэд хэдэн ХХК-д харьяалагдаж болно.
- Ажилтан бүр өөрийн бүртгэлээр нэвтэрнэ. Ерөнхий захирал (супер админ) бүх эрхтэй.
- Удирдлага, хэлтсийн бүтцийг [org-structure.md](org-structure.md)-д хөтөлнө.
- Дизайн маш чухал. Хэрэглэгч үүнийг онцолж хэлсэн.
- Систем дээр гүйлгээ хийхгүй: нягтлан бодох бүртгэл, И-баримт, банкны интеграц хэрэггүй.
  **Тодруулах:** хэрэглэгч "Гүйлгээ нрт хийхгүй ээ" гэж бичсэн. Энэ утгаар ойлгосон боловч хараахан баталгаажуулаагүй.

### Сервер

- **Туршилтын үе:** Cloudflare (Workers болон static assets). Өгөгдлийн сан нь PostgreSQL, Neon гэх мэт үнэгүй үйлчилгээ ашиглана.
- **Бодит ашиглалт:** Монголын дата төвийн VPS дээр Docker-оор ажиллуулна. Эсвэл хуулийн зөвлөгөө авсны дараа Cloudflare дээр үлдэж болно.
- Нэг код Cloudflare дээр ч, энгийн Node.js/Docker сервер дээр ч өөрчлөлтгүй ажиллах ёстой.
- Туршилтын үед ажилчдын РД, цалин зэрэг жинхэнэ хувийн мэдээлэл оруулахгүй, жишээ өгөгдлөөр туршина.
  Учир нь Хувийн мэдээлэл хамгаалах тухай хуулиар хувийн мэдээллийг гадаадад шилжүүлэхэд тухайн хүний зөвшөөрөл эсвэл хуулийн үндэслэл шаардлагатай.

### Технологи

- Хэл: TypeScript (backend, frontend хоёуланд).
- Архитектур: modular monolith. Нэг програм, дотроо модулиудад хуваагдсан, нэг өгөгдлийн сантай.
- Backend: Hono. Cloudflare Workers болон Node.js аль алин дээр ажилладаг. Cloudflare дээр тохиромжгүй тул NestJS-ийг сонгоогүй.
- Өгөгдлийн сан: PostgreSQL.
- Frontend: React, Vite, Ant Design (`mn_MN` locale).
- Дараа шийдэх: ORM, нэвтрэх систем (auth), файл хадгалах арга.

### Дизайн

- Фонт сонгохдоо монгол Ө, Ү үсэг байгаа эсэхийг заавал шалгана. Үгүй бол тэдгээр үсэг өөр фонтоор харагдаж эвдэрнэ.
  - Шалгасан, ашиглаж болно: Golos Text, IBM Plex Mono, Literata, Manrope, Montserrat, Onest, PT Serif, Prata, Raleway, Rubik, Commissioner, Exo 2.
  - Ө, Ү байхгүй: Unbounded, Wix Madefor Display.

  Instagram, X зэрэг сайтыг уншихдаа хэрэглэгчийн бүртгэлийг илрүүлэлтээс нуугддаг хөтчөөр ашигладаг тул бүртгэл хаагдах эрсдэлтэй.

## 2026-10-28 (үргэлжлэл): ажилтны хэрэгслүүд

**Ажлын дараалал.** Эхлээд дизайныг батлуулна. Дараа нь ажилтны хэрэгслүүдийг хийнэ.

**Нэг нэгээр нь хөгжүүлнэ.** Ажилтны хэсгийг нэг дор хийхгүй (хэрэглэгчийн шийдвэр). Хэрэгсэл бүрийг дараах дарааллаар хийнэ: дизайн → хэрэглэгч батлах → хийх → турших → ашиглалтад гаргах. Тэгээд дараагийнх руу шилжинэ.

**Ерөнхий санаа.** Ажилтан системийг өдөр бүр ашиглах жижиг хэрэгслүүдээр хангана. Хэрэглэгч одоогоор хоёр санаа гаргасан: PDF засах хэрэгсэл, ажлын тэмдэглэл.

### PDF хэрэгсэл: тохиролцсон төлөвлөгөө

1. **Энгийн хэрэгслүүд** (нэгтгэх, салгах, хуудас эрэмбэлэх, гарын үсэг, усан тэмдэг, хуудасны дугаар гэх мэт). Ажилтны хөтөч дотор ажиллана, файл гадагш гарахгүй, сервер хэрэггүй.
   - Stirling-PDF-ийн үнэгүй (MIT) кодоос хуулж авна. Зохиогчийг дурдана.
   - Дэлгэцийг Ant Design болон манай дүрмээр дахин хийнэ.
   - Хэрэглэгч эхний 3–5 хэрэгслийг хараахан сонгоогүй.
2. **AI-тай хэрэгслүүд** (монгол текст таних, товчлох, мэдээлэл гаргах, орчуулах). OpenRouter-оор хямд загвар ашиглана.
   - Хэд хэдэн загварыг монгол баримт дээр туршиж сонгоно.
   - Ажилчдын хувийн мэдээлэл, нууц гэрээг илгээхгүй, эсвэл мэдээлэл хадгалдаггүй үйлчилгээ үзүүлэгчийг л сонгоно.
   - AI-ийн үр дүнг ажилтан шалгадаг байна.
   - Сарын зардалд дээд хязгаар тавина. API түлхүүрийг серверт хадгална.
3. **Сервер шаардлагатай хэрэгслүүд** (Word/Excel ↔ PDF, файл багасгах). Өөрийн сервертэй болсон үед хийнэ. Stirling-PDF-ийн үнэгүй хувилбарыг серверт ажиллуулж болно.

### Судалсан эх сурвалж

- **sammyZi/pdf-tools.** Android апп, MIT. 24 хэрэгсэл болон баримт скан хийгчтэй, бүгд утсан дээр ажилладаг. Шууд ашиглах боломжгүй, зөвхөн жишээ болгоно.
- **Stirling-Tools/Stirling-PDF.** 2026-10-28-нд commit `78bea24`-ийг судалсан.
  - **Лиценз:** open-core.
    - MIT: `app/core` болон `frontend/src/editor/core` зэрэг үндсэн хэсэг.
    - Төлбөртэй: `app/proprietary`, `app/saas`, `engine`, `frontend/src/editor/{proprietary,desktop,saas,cloud}`, `frontend/src/processor` хавтсууд. Төлбөргүйгээр зөвхөн туршиж болох ба хуулахыг хориглосон.
    - Төлбөртэй хэсэгт хэрэглэгчийн нэвтрэлт ба SSO, аудит, AI, ажлын урсгал, хадгалалт ордог.
  - **Үнэгүй хувилбар:** зөвхөн үнэгүй хэсгийг `STIRLING_FLAVOR=core` эсвэл `DISABLE_ADDITIONAL_FEATURES=true`-ээр бүтээнэ. Бэлэн Docker багцад төлбөртэй хэсэг нь орсон байдаг.
  - **Ажиллах орчин:**
    - Сервер тал нь Java болон LibreOffice, Tesseract зэрэг програмууд дээр ажилладаг, Cloudflare дээр ажиллахгүй.
    - 40 гаруй хэлтэй ч монгол хэл байхгүй.
  - **Вэб хэсэг:** React 19 болон Mantine дээр бичигдсэн. Хөтөч дотор PDF боловсруулахдаа дараах сангуудыг ашигладаг:
    - EmbedPDF (`@embedpdf/*`, MIT, PDFium)
    - `@cantoo/pdf-lib` (MIT, нууц үг тавих боломжтой)
    - `pdfjs-dist` (Apache-2.0)
  - **Бусад:** монгол текст танихад `tesseract.js` (Apache-2.0)-ийг AI-тай харьцуулж туршиж болно.

## 2026-10-29 (үргэлжлэл): гацааг засав

**Асуулт.** Хэрэглэгч хөдөлгөөн жигд биш, гацаж байгаа юм шиг санагдаж байна, бодит сервер дээр байрлаагүйгээс болсон уу гэж асуусан.

**Хариулт.** Үгүй. Сервер зөвхөн эхний ачаалалд нөлөөлнө. Жигд байдал нь тухайн компьютер дэлгэцийг хэр хурдан зурахаас хамаарна. Playwright-ээр хэмжиж 3 шалтгаан олсон:
- **Хуудас нээгдэх үед.** GSAP хөдөлгөөн эхлэхийн өмнө элемент бүрийг хэмждэг. Үүнээс болж хуудас нэг нээгдэхэд хөтөч байрлалыг 50-100 удаа дахин тооцож байсан.
- **Картын бүдгэрүүлэлт (backdrop-filter).** Хамгийн их ачаалал өгч байсан. Үндсэн "Үнс" дэвсгэр нэг өнгөтэй тул бүдгэрүүлэлт харагдахгүй ч ачаалал нь хэвээр байсан.
- **Цонх нээх, мэдэгдэл гарах бүрт** бүх апп дахин зурагдаж байсан.

**Засвар**
- Хуудас, ажлын карт, график, хуанли, цонх, цэс гарч ирэх хөдөлгөөнийг хөтчийн өөрийн Web Animations-аар хийдэг болгосон. Энэ нь хөтчид суусан боломж тул шинэ сан нэмээгүй. Хөтөч эдгээрийг тусдаа урсгал дээр ажиллуулдаг тул хуудас ачаалах ажил хөдөлгөөнийг гацаахгүй. Муруйг GSAP-аас (`gsap.parseEase`) авсан тул хөдөлгөөний хэлбэр өөрчлөгдөөгүй. Чирэх, island, тоо гүйх зэрэг бусад хөдөлгөөн GSAP-аар хэвээр.
- Нэг өнгөтэй дэвсгэр (Үнс, Элс, Шарилж) дээр хуудсан доторх картууд бүдгэрүүлэхгүй. Гэрэл горимд илүү цагаан өнгөтэй болсон тул өмнөхөөсөө ялгаагүй харагдана (ΔE "Үнс" дээр 1-ээс бага, "Элс", "Шарилж" дээр 2 орчим). Хажуугийн цэс, дээд мөр, цонхнууд бүдгэрүүлэлтээ хадгална, учир нь хуудас тэдний доогуур гүйдэг. Давалгаатай дэвсгэр хэвээр, тиймээс арай хүнд.
- Цонхнууд төлвөө өөрсдөө уншдаг болсон. Ингэснээр цонх нээхэд хуудас дахин зурагдахгүй.
- Бүх дэлгэцийг нэг файлд оруулсан. Хуудас солиход сүлжээ хүлээхгүй. Эхний ачаалал 100 KB орчим нэмэгдсэн (шахсан хэмжээ 164 KB).
- Ажлын самбар дээр зөвхөн дэлгэцэнд харагдаж буй картууд хөдөлгөөнтэй гарч ирнэ.

**Хэмжилт.** GPU-гүй орчинд хэмжсэн. Жинхэнэ компьютер дээр бүх тоо илүү сайн гарна.
- Гүйлгэх үед нэг кадр зурах хугацаа 38 ms-ээс 26-28 ms болсон.
- Хулгана хөдлөхөд 35 ms-ээс 17 ms болсон (секундэд 60 кадр).
- Хуудас солих эхний 1.2 секундэд зурсан кадр ихэнх хуудсанд 1.5-3.5 дахин олширсон.
- Хуудас нээх үеийн дахин байрлуулах ажил 100 ms-ээс 10-20 ms болсон.
- Харьцуулалт: Pane-ийн demo ижил орчинд гүйлгэхэд кадр бүрт 89 ms зарцуулж байна, манайх 26 ms.

## 2026-10-29 (үргэлжлэл): Бичиг хэрэг

**Хүсэлт.** Хэрэглэгч "Бичиг хэрэг" гэсэн шинэ хэсэг хүссэн. Ажилтан хэрэгтэй баримтаа бичиг хэргийн ажилтнаас хүснэ: юунд, яаж ашиглах, цаасаар уу, цахимаар уу. Дараа нь "ажилтанд хэрэг болох маягтууд тэнд байя, түүнийг бичиг хэрэг өөрөө оруулна" гэж нэмсэн.

Ноорог одоо зөвхөн самбартай. Хуучин `#draft-pdf` хаяг шинэ газар руу шилжинэ. Самбар дээрх PDF картаас "PDF засах" дарвал энд нээгдэж, хадгалахад самбарт буцна. Хайлтаар (Ctrl K) "PDF" гэж бичвэл олдоно.

**Бичиг баримт хуудас.**
- 3 бүлэг:
  - **Танд хамаарах:** зөвхөн тухайн ажилтанд хуваалцсан гэрээ, тушаал, тодорхойлолт. 7 хоногийн дотор нэмэгдсэн нь "Шинэ" тэмдэгтэй.

**Хүсэлт.** "Ажилтан бүрт гэрээний драфт бэлддэг ажил гардаг, тэрийг бичиг баримт хэсэгт нэмэх гэсэн юм. Санхүүгийн захирал, хуульч 2-т зэрэг очдог байна. Мөн олон файл дээр биш 1 файл дундаа засварлаж хиймээр байна."

**Таны системээс хэвээр авсан зүйл.**

## 2026-10-30: Сарын тайлан, 25-р хувилбар (хэрэглэгчийн батлах хүлээгдэж байна)

**Хэрэглэгчийн хариулт.** "Сарын сүүлийн өдөр өгдөг, тэрэн дээр шууд удирдлага нь kpi үнэлгээ өгдөг."

- KPI-ийн шалгуур, жин, урамшууллын хувийг хэрэглэгч хэлээгүй. Түгээмэл загвараар хийж, ХХК бүр өөрчилдөг болгосон.

**Байршил.** "Тайлан" цэс хоёр табтай болсон:
- "Үзүүлэлт": өмнөх график, тоонууд.
- "Сарын тайлан": шинэ хэсэг. Хаяг нь `#insights-reports`, нэг тайлан `#insights-report-<хүн>-<сар>`.

**Хэн тайлан өгөх, хэн үнэлэх.**
- ERP хэрэглэдэг, ажиллаж буй (чөлөөтэй биш) ажилтан бүр тайлан өгнө.
- Шууд удирдлагыг дараах дарааллаар тодорхойлно:
  1. Ажилтны бүртгэлд тусгайлан заасан хүн (Хүний нөөц → ажилтны форм → "Шууд удирдлага").
  2. Үгүй бол хэлтсийн дарга (Хүний нөөц → Бүтэц → хэлтэс засах → "Хэлтсийн дарга").
  3. Хэлтсийн дарга өөрөө бол захирал (гэрээний процессын "Гүйцэтгэх захирал").
  4. "Байхгүй, сарын тайлан өгөхгүй" гэж сонгосон хүн тайлан өгөхгүй. Жишээнд Ерөнхий захирал ийм байна.

**Ажилтан.**
- Тайлан урьдчилан бөглөгдсөн байна: тухайн сард дуусгасан ажил ("Ажил" тэмдэгтэй), явуулсан гэрээ ("Гэрээ" тэмдэгтэй). Ажилтан засаж, хасаж, нэмнэ.
- Мөрийн төгсгөлд Enter дарахад шинэ мөр нэмэгдэнэ. Хоосон мөрөнд Backspace дарахад мөр хасагдана.
- Сарын дотор шинээр ажил дуусвал "Системээс 2 ажил нэмэх" товч гарна.
- Асуудал, санал; дараа сарын төлөвлөгөө.
- Бичсэн нь автоматаар хадгалагдана. "Удирдлагад илгээх" дарахад илгээгдэнэ. Хийсэн ажил, төлөвлөгөө хоосон бол алдаа гарна.
- Хажууд нь үнэлэх шалгуур, өмнөх сарын төлөвлөгөө, системд бүртгэгдсэн тоо (дууссан ажил, хугацаандаа, уулзалт) харагдана.

**Шууд удирдлага.**
- «Миний хийх»-д "Үнэлэх" гарна. Цэс, таб дээр тоо нь харагдана.
- Тайлангийн доор 5 шалгуур тус бүрд 1–5 оноо өгнө. 100 оноо, шатлал, урамшууллын хувь шууд тооцогдож харагдана.
- "Санал, зөвлөмж" бичнэ.
- "Төлөвлөгөөг ажил болгон бүртгэх" асаалттай бол төлөвлөгөөний мөр бүр ажилтны "Ажил" болно. Хугацаа нь дараа сарын сүүлийн өдөр. Дараа сард тэр ажлыг дуусгавал тайланд нь өөрөө орно.
- "Буцаах" дарж, засах зүйлээ бичнэ. Ажилтан засаад дахин илгээнэ.

**Захирал, хүний нөөц.**
- Бүх ажилтны хүснэгтийг сараар (сүүлийн 3 сар) харна: төлөв, илгээсэн огноо, оноо, үнэлгээ, урамшуулал.
- "Excel-ээр татах" нь шалгуур бүрийн оноо, нийт оноо, үнэлгээ, урамшууллын хувь, санал, зөвлөмжийг гаргана. Урамшуулал тооцоход ашиглана.
- Удирдлага зөвхөн өөрийн багийг, ажилтан зөвхөн өөрийн тайланг харна. Бүх тайланг захирал, хүний нөөц, хамгийн дээд удирдлага харна. Бодит системд хүний нөөцийн эрхийг тусад нь олгоно.

## 2026-10-30: Бичиг хэрэг: скан хийсэн цаасан баримтыг AI-аар таньж хавтаслах (26-р хувилбар, AI түлхүүр хүлээгдэж байна)

**Хэрэглэгчийн хүсэлт.** "Тайланг түр үлдээе. Одоо бичиг хэргийн ажилтан хариуцах компанийн бичиг хэргийн хавтсыг AI-тай холбоё. Манайд цаасан гэрээ маш олон байгаа. Скан хийгээд оруулахад автоматаар таниад, ялгаж хавтасладаг болгоё. OpenRouter-ийн хямд AI загварын API ашиглая. API-г дараа нь өгнө, одоо хийж эхэл." Сарын тайлангийн ажил түр зогссон.

**Хийсэн зүйл.**
- Бичиг хэрэг → "Скан оруулах" таб (`#docs-scan`).
- Ажилтан олон файл (PDF, JPG, PNG) зэрэг оруулна. Утсаар зураг авч оруулж болно.
- AI баримт бүрийг уншаад дараах зүйлсийг санал болгоно:
  - аль ХХК, аль хавтас (Гэрээ, Тушаал, Албан бичиг…);
  - баримтын нэр, дугаар, огноо, харилцагч, дүн, дуусах хугацаа;
  - товч агуулга, итгэлийн түвшин;
  - шалгах зүйл: гарын үсэг, тамга алга, хугацаа дууссан, бүдэг скан гэх мэт.
- Ажилтан шалгаж засаад "Хавтаслах" дарна. Итгэлтэй танигдсаныг "Танигдсаныг хавтаслах"-аар нэг дор хавтаслана. Буцаах боломжтой.
- Хавтасласан баримтын дугаар, огноо, харилцагч, дүн хадгалагдана:
  - хавтас дээр баримтын өөрийн огноо, дугаар харагдана;
  - хайлтаар дугаар, харилцагчаар олдоно;
  - хавтсанд ижил дугаартай баримт байвал анхааруулна.
- Хүлээлгийн скан бүх ХХК-д нэг байна, учир нь холимог цаасыг ялгах нь зорилго. ХХК-ийг AI санал болгоно.
- AI холбогдоогүй үед мэдээллийг гараар бөглөнө.
- Туршилтын хуудсанд "Жишээ скан нэмэх" товч 4 жишээ скан нэмнэ. Тэдгээрийг "Жишээ" гэж тэмдэглэсэн бөгөөд AI-ийн жинхэнэ хариу биш, дэлгэцийг харуулах зорилготой. Түлхүүр ирсний дараа жинхэнэ AI-ийн хариугаар солино.

**Бүтэц.**
- AI-ийн түлхүүр зөвхөн серверт (`web/server/`) хадгалагдана, хөтөч рүү хэзээ ч очихгүй.
- Сервер Node 22 дээр нэмэлт сан суулгалгүй ажиллана: `OPENROUTER_API_KEY=… node server/main.ts`. Vite-ийн туршилтын сервер `/api`-г түүн рүү дамжуулна.
- Хөтөч скан бүрийн эхний 2, сүүлийн 1 хуудсыг 1800 px зураг болгож сервер рүү илгээнэ. Сервер OpenRouter-оос бүтэцтэй (JSON schema) хариу авч, хэлбэрт нь тааруулж цэвэрлэнэ.
- Нэг загвар ажиллахгүй бол OpenRouter дараагийнхыг нь автоматаар оролдоно (`models` жагсаалт).
- Туршилтын хуудас (claude.ai) гадагш хүсэлт явуулж чаддаггүй тул тэнд AI ажиллахгүй. Жинхэнэ AI-г компанийн сервер дээр байршуулсны дараа ашиглана.
- Серверийг үйлдвэрлэлд ERP-ийн нэвтрэлтийн ард байрлуулна. Одоогоор нэвтрэлтгүй.

**OpenRouter-ийг шалгасан нь (2026-10-30).**
- Төлбөртэй үйлчилгээ, HTTP API-аар ажиллана. Манай кодонд түүний сан суулгаагүй.

  - OpenRouter хүсэлтийн агуулгыг хадгалдаггүй (лог асаагаагүй үед). Зөвхөн токены тоо, үнэ зэрэг хэрэглээний мэдээллийг хадгална. Бүх хүсэлтийг хүүхдийн хүчирхийллийн агуулга (CSAM) байгаа эсэхээр шалгадаг.

## 2026-10-31: Компьютер асахад ERP автоматаар нээгдэх (санал, бодит сервертэй хамт)

  - Дүрс дээр удаан дарахад гарах товчлол (manifest `shortcuts`): Android, компьютерт ажиллана. iPhone-д ажиллахыг баталгаажуулаагүй.
  - Өглөөний тойм мэдэгдэл.

**Санал.**

  - дүрс дээр "таны хийх зүйл"-ийн тоо;

## 2026-10-31: Хүний нөөц → Ирц: Timely-ээс татах (28-р хувилбар, Timely-ийн түлхүүр хүлээгдэж байна)

**Хэрэглэгчийн хүсэлт.** "https://developer.timely.mn/#description/introduction ирцийг оруулъя, судлаарай." Энэ нь хэрэглэгчийн Хүний нөөцийн төлөвлөгөөний 8-р модуль "Ирц — Timely-тэй холболт" ([Claude Docs](https://claude.ai/artifact/6SQenwj6xnSbqVdmQYRmh8)). Төлөвлөгөөний бүтцээр нь шинээр хийсэн.

**Timely API-г шалгасан нь (2026-10-31).**
- Timely OpenAPI 1.0.0, хаяг нь `https://api.timely.mn/openapi`. Баримт developer.timely.mn дээр монгол, англиар бий.
- Зөвхөн мэдээлэл уншдаг API. Гадны сан суулгаагүй, зөвхөн HTTP хүсэлт. Манай талд телеметри, ажиллуулдаг гадны код байхгүй.
- Түлхүүр:
  - Timely-ийн админ вэбийн Тохиргоо → API түлхүүр хэсэгт үүсгэнэ. `timely_sk_`-ээр эхэлнэ, зөвхөн үүсгэх үед нэг удаа харагдана;
  - нэг түлхүүр нэг байгууллагад харьяалагдана. Хугацаагүй, идэвхгүй болгож болно;
  - эрх: `attendance:read` (ирц), `employee:read` (ажилтан), `company:read` (байгууллага).
- Нэвтрэх: түлхүүрээ `POST /auth/token`-д өгч 1 цагийн токен авна. Токен авах хүсэлт нэг IP хаягаас минутад 10-аас ихгүй байна.
- Замууд: байгууллага; ажилтны жагсаалт ээлжийн амралтын үлдэгдэлтэй; нэг ажилтны мэдээлэл (цалин, банкны данстай); нэг ажилтны өдөр бүрийн ирц (ирсэн, явсан цаг); нэг ажилтны сарын дүн (ажиллавал зохих, ажилласан өдөр, цаг); хүсэлтийн төрөл; бүх ажилтны тойм, өдрөөр, нийт.
- Огноо Улаанбаатарын цагаар.
- Өдрийн ирцийн нарийн мэдээллийн (хоцролт, хүсэлт гэх мэт) бүтцийг баримтжуулаагүй. "Шинэ хувилбарт өөрчлөгдөж болно" гэжээ. Тиймээс одоо зөвхөн баримтжсан талбаруудыг ашигласан. Түлхүүр ирэхэд жинхэнэ хариуг харж, хоцролт, чөлөө зэргийг нэмнэ.
- Буруу түлхүүрээр хандахад 401 алдаа, "API түлхүүр буруу эсвэл хүчингүй байна" гэж монголоор хариулсан. API ажиллаж байна.

**Хийсэн зүйл.**
- Хүний нөөц → "Ирц" таб (`#hr-attendance`):
  - дээд талд: дундаж ирц, ажлын өдөр, бүрэн ажилласан, ирц 80%-иас доош ажилтны тоо;
  - "Ирц доогуур" жагсаалт, хэлтсээрх дундаж ирц;
  - "Ажилтнуудын ирц" хүснэгт: ажилласан ба ажиллавал зохих өдөр, цаг, ирцийн хувь, ээлжийн амралтын үлдэгдэл. Хэлтсээр шүүнэ, ирцээр эрэмбэлнэ;
  - "Тулгагдаагүй ажилтан": зөвхөн Timely-д, зөвхөн ERP-д байгаа ажилтан;
  - сүүлийн 3 сар, "Шинэчлэх" товч. Хуудас нээлттэй үед 5 минут тутам өөрөө шинэчлэгдэнэ.
- Ажилтны ирц (`#hr-attendance-<ажилтан>`):
  - сарын календарь. Өдөр бүр өнгө, цаг эсвэл тэмдэгтэй: Ирсэн, Бүртгэл дутуу, Бүртгэлгүй, Ээлжийн амралт, Амралтын өдөр;
  - өдөр бүрийн ирсэн, явсан цаг, хугацаа, дундаж ирсэн цаг;
  - ээлжийн амралтын эрх, ашигласан, үлдсэн хоног, авсан хугацаанууд;
  - ажилтны хуудаснаас "Ирц" товчоор орно.
- Ажилтныг регистрийн дугаараар тулгана.
- ХХК-ийг Timely-ийн байгууллагатай нэрээр нь холбоно. Нэр нь өөр бол жагсаалтаас сонгож холбоно.
- Timely холбогдоогүй үед "Жишээ ирц харах" товч зохиомол сар харуулна. Ажилтнууд нь манай жишээ ажилтнууд. Энэ нь жишээ гэдгийг төлөвийн мөрөнд бичнэ.

**Шийдвэр.**
- Түлхүүр зөвхөн серверт хадгалагдана, хөтөч рүү очихгүй. Сервер `TIMELY_API_KEYS` хувьсагчаас уншина. Хэд хэдэн ХХК-ийнхыг таслалаар зааглана.
- Төлөвлөгөөнд админ түлхүүрийг ERP дотроос оруулна гэсэн. Үүнийг нэвтрэлт, эрхийн шалгалттай бодит сервер хийсний дараа нэмнэ. Тэр болтол орчны тохиргоонд хадгална.
- Цалин, банкны данс (`/employees/info`) татахгүй, учир нь ирцэд хэрэггүй. Түлхүүрийн `employee:read` эрх эдгээрийг нээдэг тул энэ зааг манай кодонд байна.
- Ирцийн хувь = ажилласан цаг ÷ ажиллавал зохих цаг. 100%-иас дээш гарахгүй. Цаг байхгүй бол өдрөөр тооцно.
- Тухайн сард өнөөдрийг хүртэлх хугацааг тооцно.
- Сарын дүнг ажилтан бүрээр, баримтжсан замаар (`/employees/attendance-summary`) 4-өөр зэрэг асууна. 50 ажилтантай бол 5 минут тутам 51 хүсэлт явна.

- Бямба, Ням гарагийг амралтын өдөр гэж үзнэ. Баярын өдөр, ээлжийн ажлын хуваарийг Timely-ийн жинхэнэ хариунаас авна.
